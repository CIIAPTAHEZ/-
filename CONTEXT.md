## 1. ОБЩЕЕ ОПИСАНИЕ

Локальное веб-приложение для автоматизации сбора, хранения, анализа и визуализации данных по рекламациям заказчиков и операционному контролю качества на производстве (сантехническая продукция: сиденья для унитазов, смесители).

**Расположение:** `C:\Users\Aleksandr\Desktop\claims_system\`

**Технологии:**
- Бэкенд: Python 3.14, Flask 3.1.3
- БД: SQLite (файл `data/claims.db`)
- Фронтенд: HTML, CSS, JavaScript (vanilla), Chart.js 4.4.3 (локальная копия)
- Импорт Excel: openpyxl (.xlsx), xlrd 2.0.2 (.xls)
- Отчёты: reportlab 5.0.0 (PDF), openpyxl (XLSX), csv (CSV)
- Упаковка: PyInstaller 6.21.0

### Параметры фильтрации
- `search` — поиск подстроки по текстовым полям
- `date_from`, `date_to` — диапазон дат
- `eq_<поле>` — точное совпадение
- `in_<поле>` — входит в список (значения через запятую)
- `min_<поле>`, `max_<поле>` — числовой диапазон

### Сортировка
- `sort_by=поле1;поле2` — многоуровневая (поля через `;`)
- `sort_dir=asc;desc` — направления через `;`

5. **Исправлены подписи значений на круговой диаграмме (аналитика).**
   - Причина: для элемента-дуги (Arc) у Chart.js координаты `x/y` — это центр круга, поэтому все значения рисовались в центре и накладывались друг на друга.
   - Исправление: для круговой диаграммы позиция подписи вычисляется по средней дуге каждого сегмента (внутри сегмента на 62% радиуса); для мелких сегментов (когда текст не помещается) подпись выносится наружу с линией-выноской и белой плашкой.
   - Текст рисуется с белой «гало»-обводкой (`drawChartLabel`) для читаемости на любом фоне.
   - Столбчатая и линейная диаграммы не изменены.
6. **Устранено наложение внешних выносных подписей круговой диаграммы.**
   - Итеративный алгоритм `resolveExternalLabelOverlap()` заменён на детерминированное колоночное размещение:
     - подписи делятся на левую и правую колонку относительно центра круга;
     - внутри каждой колонки подписи распределяются равномерно по вертикали с фиксированным шагом (14–26 px) — это исключает пересечения по построению;
     - колонки удерживаются в пределах области диаграммы (клиптинг по x), чтобы широкие плашки не выходили за правую границу/легенду;
     - линии-выноски по-прежнему связывают каждую подпись со своим сегментом.
   - Проверено на 6 сценариях (кучка сверху, снизу, смешанная, вокруг всего круга 12 и 18 подписей, широкие значения) — пересечений, попаданий внутрь круга и выхода за границы нет.
7. **Добавлена вкладка «Микролифт» (время опускания микролифта).**
   - Новая вкладка между «Операционный контроль» и «Аналитика» для ручного ввода замеров времени опускания сидений с микролифтом по 21 форме.
   - Три зоны: ввод данных (выбор формы с быстрым поиском, целое число секунд 1–60, комментарий), сводная статистика по всем формам (n, среднее, мин, макс, размах), история замеров выбранной формы с удалением записи (с подтверждением).
   - Хранение: таблица `micro_lift` в SQLite (`id`, `form_id`, `time_seconds`, `created_at`, `comment`). Создаётся автоматически миграцией в `init_db()`.
   - Список форм задан в `config.MICROLIFT_FORMS` (21 позиция «Форма 01»…«Форма 21») — расширяется без перекомпиляции.
   - Статистика считается на сервере (SQL GROUP BY + AVG/MIN/MAX), округление среднего до 0.1 с.
   - В аналитике добавлена столбчатая диаграмма среднего времени по формам с планками погрешностей (мин–макс) через Chart.js.
   - API: `/api/microlift/forms`, `/api/microlift/stats`, `/api/microlift` (GET по form_id, POST), `/api/microlift/<id>` (DELETE).
   - Проверено: 38 автотестов API + страниц (создание/валидация/статистика/удаление) на временной БД — без ошибок.

   - Формы теперь хранятся в отдельной таблице `micro_lift_forms` (`id`, `name`, `created_at`). Названия можно самостоятельно менять, добавлять и удалять через модальное окно «Управление формами» (кнопка на вкладке) — без перекомпиляции.

   - В аналитике у диаграммы среднего времени добавлен селектор типа замерения.
   - API форм: POST /api/microlift/forms (создать, уникальность имени), PUT /api/microlift/forms/<id> (переименовать), DELETE /api/microlift/forms/<id> (удалить форму вместе с замерами).
   - Миграция обратно совместима: в существующих БД добавляется `measure_type` (старым записям — `seat`), создаётся и заполняется таблица форм (21 по умолчанию), существующие записи не теряются.
   - Проверено: 42 автотеста (CRUD форм, типы, статистика по типам, история с фильтром, каскадное удаление, HTML/статика) + 6 проверок миграции старой БД — без ошибок.

10. **Печать вкладок «Журнал претензий» и «Операционный контроль».**
    - В тулбары обеих вкладок добавлены кнопки «🖨 Печать».

    - Проверено: 10 JS-тестов функции формирования печатного блока + 8 проверок страниц/стататики — без ошибок.
